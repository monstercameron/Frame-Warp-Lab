# Frame Warp Lab

A Direct3D 12 rendering experiment investigating presentation pacing, reprojection and frame generation.

Read [experiment-plan.md](experiment-plan.md) for the prioritized experiment, [research.md](research.md) for the research and architecture, [test-scene.md](test-scene.md) for the proposed test scene, and [spacewarp-references.md](spacewarp-references.md) for related implementations and SDKs. [AGENTS.md](AGENTS.md) records the engineering and measurement rules.

## Current baseline

The native application renders a CPU-driven procedural Motion Lab scene with selectable deterministic camera paths (`corridor_sway`, `fast_pan`, `occlusion_sweep`, `camera_cut`, `pure_rotation`) and low-latency interactive manual controls (`manual`: Win32 Raw Input mouse deltas with left-click drag or right-click/`M` mouse-look, `ESC` unlock, `WASD`/`Q`/`E` move, arrow keys look, `1-7` presentation modes including `6` `dlss_g` and `7` `dlss_g_warp`, `X` cycle DLSS-G multiplier `2x..6x`/`dynamic`, `U` selective tile repainting toggle, `T` tile cache diagnostic map toggle, `Y` perceptual tile priority heatmap toggle, `B` VRS mode cycle, `K` adaptive deadline scheduler toggle, `G` async dual-queue toggle, `L` pacer mode, `H` holes view, `O` HUD toggle, `F` Reflex optical flash box toggle, `V` VSync toggle, `C` cycle paths, `[`/`]` divider, `-`/`=` stress, `P`/`Space` pause, `R` reset). Shaders are compiled offline at build time via Windows SDK `dxc.exe` to **Shader Model 6.0 (`vs_6_0`/`ps_6_0`/`cs_6_0`)** with wave-level atomic reductions (`WaveActiveCountBits`), CPU-precomputed relative camera homography matrices, five specialized presentation PSOs (`simple`, 0-depth `rotation_homography`, `depth_fast`, `depth_full`, and `synthesis`), a 4-RTV geometrically aligned DLSS-G inputs PSO (`present_dlss_inputs_ps.cso`), and a three-pass **Perceptually Amortized Rendering (PAR)** selective tile compute pipeline (`tile_vis_classify_cs.cso` + 8-bin priority-bucketed + 3D STBN `tile_admit_cs.cso` + GPU `ExecuteIndirect` `tile_shade_indirect_cs.cso`) that reprojects cached `16×16` tiles and repaints the highest-priority dirty/disoccluded/aging tiles within a configurable per-frame tile budget (`tile_budget` `5..100`, `tile_policy` `priority_stbn|fifo`). When the NVIDIA Streamline SDK (`v2.14.16` ARM64) is present in gitignored `third_party/streamline/`, the app links `sl.interposer.lib`, integrates **Streamline Reflex, PCL, and DLSS Frame Generation** (up to 6× Multi Frame Generation and Dynamic MFG on RTX Spark N1X), tags target-camera-aligned clip-space depth, motion vectors, and HUD-less color via a 3-slot dual-fence ring, and exposes both pure `dlss_g` and experimental Space Warp + DLSS-G (`dlss_g_warp`) with a 1.5%-hole artifact safety guard. Without the SDK, it builds cleanly in standalone D3D12 mode. The loop uses bounded timeout + device-removal checks on waits/fences, paces `Present()` entry with a DWM phase-locked high-resolution deadline pacer (or Streamline Reflex + DLSS-G pacer when DLSS-G is active), executes scene rendering (with optional D3D12 Variable Rate Shading Tier 1 `uniform_2x2` / Tier 2 `foveated` or visibility-guided selective tile compute) and late synthesis/presentation on independent D3D12 command queues (`NORMAL` scene queue + `HIGH`-priority present queue backed by a 3-slot source history ring), optionally adapts rendering/VRS/DLSS-G/synthesis tiers automatically via a deadline-aware GPU headroom scheduler, and emits NVIDIA PC Latency (PCL) ETW TraceLogging and Streamline PCL markers (`PCLStatsTraceLoggingProvider`, including late-warp markers) for FrameView, NVIDIA App, and PresentMon (configurable via `instrumentation`: `minimal`, `standard`, `diagnostic`). It outputs offscreen linear color, linear view-space depth, 2D screen-space motion vectors, packed visibility, and per-tile cache status maps, and composites a late 1x1-shaded 2D HUD layer with a 128-frame color-coded frametime graph, 15 Hz-throttled smoothed Present-cadence FPS/frametime readout, GPU pass timings, tile cache ratio, input-to-present latency, and center reticle. It does not yet provide verified physical displayed-frame scanout timing (which requires elevated PresentMon/FrameView capture). It is not a benchmark. See [DEVLOG.md](DEVLOG.md) for development history.

## Build and run on Windows ARM64

With Visual Studio 2022 C++ Build Tools, the ARM64 compiler, Windows SDK, and CMake installed, run in PowerShell from this folder:

```powershell
cmake -S . -B build -G 'Visual Studio 17 2022' -A ARM64
cmake --build build --config Release
./build/Release/frame_warp_lab.exe
```

Use `--config Debug` to enable the D3D12 debug layer if available, or `--config Release` for low-overhead ARM64 NEON SIMD pacing measurements. Close the window to exit. To enable NVIDIA Streamline/DLSS-G support locally, unpack the official NVIDIA Streamline ARM64 SDK (`v2.14.16`) into `third_party/streamline/` (gitignored) before configuring CMake; runtime DLLs are automatically copied next to the executables. Set `FRAME_WARP_SL_LOG_DIR=<path>` to capture verbose Streamline diagnostic logs. DLSS-G requires the application window to be focused in the foreground on an active desktop (`WinSta0\Default`) to actively interpolate frames; run `./scripts/verify_dlssg_foreground.ps1` from a normal interactive Windows Terminal to verify `2x–6x` and Dynamic MFG live.

## CLI foundation

The console executable emits JSON and uses exit code 0 for success and 1 for errors. Start the application separately, then use:

```powershell
./build/Debug/frame_warp_cli.exe help
./build/Debug/frame_warp_cli.exe start
./build/Debug/frame_warp_cli.exe instances
./build/Debug/frame_warp_cli.exe status <pid>
./build/Debug/frame_warp_cli.exe events <pid>
./build/Debug/frame_warp_cli.exe trace <pid> [limit] [summary]
./build/Debug/frame_warp_cli.exe set <pid> <key> <value>
./build/Debug/frame_warp_cli.exe pause <pid>
./build/Debug/frame_warp_cli.exe resume <pid>
./build/Debug/frame_warp_cli.exe reset <pid>
./build/Debug/frame_warp_cli.exe capabilities
./build/Debug/frame_warp_cli.exe stop <pid>
```

`start` launches the executable next to the CLI and returns its process ID; `ready: false` means the command does not wait for initialization. `instances` discovers application windows, including hidden ones. `status` reads local shared state for a specific process and reports completed present calls, resize count, client size and nominal Windows display modes. These are not displayed-frame measurements. Windows' enumerated highest nominal refresh for the active resolution is not a verified monitor upper bound, and actual displayed timing is unavailable. `stop` requests a normal window close and does not wait for exit. `capabilities` queries a newly created default D3D12 device, not necessarily the running instance's adapter, reporting adapter identity, DXGI tearing support and VRS tier/tile size; VRS support does not mean VRS rendering is implemented.

`events` reads a bounded in-memory journal of the 64 most recent runtime lifecycle, resize and scene-control events, with UTC timestamps and sequence numbers. Events are available only while the instance's shared state exists; the journal is not persisted, and detailed frame traces and error events are not yet implemented. A concurrent overwrite can cause a record to be omitted from a snapshot. Shared state uses a local Windows named mapping and the process's default security descriptor; it is intended for local inspection, not a remote interface.

`trace` reads up to the 256 most recent per-frame telemetry records from the bounded in-memory ring buffer (pass `summary` as the fifth argument to omit individual sample records) and reports frame-kind counts (`rendered`, `repeated`, `warped`, `generated`, `combined`, `dlss_generated`, `dlss_warped`, `fallback`), `dlssg_frames_presented`, `async_overlaps`, `missed_deadlines`, and min/median/p95/max summaries for CPU `Present()` entry interval, CPU source age, input-to-present latency, CPU stage timings (`sim_cpu_us`, `render_submit_cpu_us`, `present_call_cpu_us`), D3D12 GPU timestamp durations (`scene_gpu_us` and `present_gpu_us`), GPU-measured `invalid_pixel_ratio` and `temporal_recovered_ratio`, and selective-tile `shaded_tile_ratio` / `total_deferred_tiles`. `set` updates runtime parameters asynchronously: `mode` (`full_render`, `repeat`, `reproject`, `frame_gen`, `combined`, `dlss_g`, `dlss_g_warp`), `dlssg_mult` (`2`, `3`, `4`, `5`, `6`, `dynamic`), `pacer` (`deadline`, `vsync_only`, `unlocked`), `target_fps` (`0` for exact DWM display refresh or `30..500`), `async_gpu` (`on`, `off`), `vrs` (`off`, `uniform_2x2`, `foveated`), `selective_tiles` (`on`, `off`), `tile_budget` (`5..100`), `tile_policy` (`fifo`, `priority_stbn`), `auto_tile_budget` (`on`, `off`), `cache_sharpen` (`on`, `off`), `fixed_dt_us` (`0..100000`), `adaptive` (`on`, `off`), `adaptive_dlssg` (`on`, `off`), `instrumentation` (`minimal`, `standard`, `diagnostic`), `divider` (`1..8`), `vsync` (`on`, `off`), `view` (`final`, `depth`, `motion`, `holes`, `vrs`, `tiles`, `priority`), `path` (`corridor_sway`, `fast_pan`, `occlusion_sweep`, `camera_cut`, `manual`, `pure_rotation`), `stress` (`0..64`), `overlay` (`on`, `off`), and `flash` (`on`, `off`). Additional deterministic validation commands: `step <pid> <frames>` and `capture <pid> <tag> [step_frames]` (writes lossless binary `.ppm` backbuffer captures at exact virtual-clock timestamps).

The CLI does not yet manage persistent capture files or measure physical input-to-photon latency or display scanout timing directly (use FrameView/PresentMon alongside the emitted PCL markers).

`status` reports the Motion Lab timeline and pause state. `pause`, `resume` and `reset` queue scene-control requests; inspect `status` to confirm they were applied. Reset returns the timeline to zero and preserves the pause state. The scripted camera and ball movement are functions of scene time; real-time execution and frame sampling are not yet a deterministic capture or benchmark system.
